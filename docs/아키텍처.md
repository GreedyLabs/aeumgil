# 서비스 아키텍처

## 실행 구조

```text
App Router page / Server Action
          ↓
Repository 인터페이스 → LiveRepository
          ├─ PostgreSQL 카탈로그·사용자 데이터
          ├─ 도메인 순수 함수: 매칭·일정·혼잡·적합성
          ├─ 공공 API 클라이언트 → 공유 응답 캐시
          └─ 선택적 에이전트 루프 → 같은 도메인 함수와 조회 도구
```

화면 데이터는 [Repository](../apps/web/src/domain/repository.ts)를 통해 가져온다. [팩토리](../apps/web/src/data/index.ts)는 항상 `LiveRepository`를 반환한다. 런타임 목 저장소·데이터소스 전환 환경변수는 없다. 인증과 쓰기 검증은 서버에서 수행한다.

도메인 모델은 `LocalizedText`의 `ko/en`과 선택적 `zh-CN/zh-TW/ja/de/fr` 필드를 사용한다. 공식 관광 안내는 검증된 언어별 원천으로 보강하고 UI·편집 테마 문구는 정적 사전에서 선택한다. 사용자가 작성한 이름·소개·리뷰·개인 코스 제목·메모에는 번역 사전을 적용하지 않는다. [다국어·관광 미디어](다국어-관광미디어.md)의 원문·ID·캐시 경계를 따른다.

## 추천 코스 구성

[curated-courses.json](../apps/web/src/domain/curated-courses.json)은 여러 날 머무는 편집 코스의 장소 ID·일차·시작/관광 종료 시각·체류시간·공식 참고 링크의 정본이다. [적재 스크립트](../apps/web/scripts/expand-curated-courses.mjs)는 실제 DB 장소의 이름·지역·좌표를 대조하고 하루 체류·이동 총량과 중복을 검증해 카탈로그 템플릿으로 저장한다. 수집은 앱 부팅이나 화면 조회에서 실행하지 않는다.

편집 코스는 첫날 점심 이후 도착과 귀가일 오후 관광 종료를 기준으로 재구성한 에움길 제안이다. 원문의 상품·기사 전체를 복제한 일정이 아니며 `Theme.sources`와 `Theme.planningNote`로 출처와 개별 예약·휴무·접근 조건을 전달한다. 사진은 관광정보 카탈로그의 원천을 사용한다. 도착·귀가 시각이 실제 집 출발·도착 시각을 뜻하지 않는다.

DB 어댑터는 해당 템플릿에 `Course.preserveStopOrder`를 지정한다. `composeCourse`로 조건을 적용한 뒤 이 표시가 있으면 에이전트/혼잡 재정렬을 건너뛰고 일자별 방문 순서를 유지해 `scheduleCourse`로 마무리한다. 일반 템플릿은 기존 에이전트와 결정형 대체 흐름을 사용한다. 추천 일수는 1~5일이며 기간을 줄이면 뒤 날짜를 제외하고, 기본 기간보다 늘리면 실제 후보 풀로 다시 구성한다. 기간·이동수단을 바꾼 코스가 출처에 제시된 기본안과 같다고 보장하지 않는다.

`scheduleCourse(course, spots, mode, { eats, stays })`는 관광지·식당·숙소의 연속 이동을 직전 항목 종료 이후에 더한다. 장소 체류와 이동을 겹치지 않고, 조건상 늦거나 지나치게 먼 도보 방문은 제외하며 실제 남은 관광 일차를 정규화한다. 날짜가 바뀔 때 좌표 계산을 새로 시작하므로 집에서 첫 장소·숙소에서 다음 날 첫 장소·마지막 귀가 이동은 이 계산에 포함하지 않는다. 지도는 방문 순서와 좌표 기반 추정이며 영업시간·예약·막차·실도로를 모두 검증한 경로가 아니다.

저장 취향의 페이스·동행은 명시하지 않은 추천 조건만 보충한다. `Course.appliedOptions`가 실제 합쳐진 조건을 화면과 개인 코스 복사로 전달하며 적용 안내도 함께 제공한다. 명시 URL/입력 조건이 우선이다.

## 카탈로그와 사용자 데이터

[스키마](../apps/web/src/server/db/schema.ts)는 공공 카탈로그와 사용자 데이터를 분리한다.

- `spot_profile`, `course_template`, `course_template_item`, `commerce_profile`: 관광지·추천 템플릿·식당/숙소.
- `saved_theme`, `personal_course`, `review`, `visit`, `onboarding_preference`, `user_profile`: Keycloak `sub`에 연결한 앱 데이터.

카탈로그 수집은 운영 보조 명령으로 실행한다. 앱 부팅 때 수집·시드를 실행하지 않는다. `design/data.ts`와 런타임 샘플 평점·가상 장소는 제거되었다. 상세가 부족하면 실제 DB 기본정보와 미제공 상태를 유지한다.

개인 코스는 추천 복사 또는 빈 일정에서 시작하고 이동수단·기본 하루 출발 시간과 날짜별 출발 시간을 함께 저장한다. `personal_course.day_start_times`는 별도로 정한 양의 안전 정수 일차와 `HH:mm`을 최대 30개 담는 JSONB이며 기본값은 빈 객체다. 해당 일차의 값이 없으면 `startTime`을 사용한다. 추천 복사는 각 날짜의 첫 방문 시각을 가져와 첫날 오후·다음 날 오전 구성을 보존하고, 개인 편집기는 선택한 날짜의 출발 시간을 바꾸거나 기본 시간으로 되돌릴 수 있다. 이후 시각은 현재 출발 시간·순서·체류와 이동 추정으로 다시 계산한다.

추천의 각 항목 시각은 선택적 `notBeforeTime`으로 `items` JSON 안에 복사한다. [schedulePersonalCourseDay](../apps/web/src/domain/personal-course-schedule.ts)는 이전 체류·이동 뒤 계산한 도착 시각과 `notBeforeTime` 중 늦은 시각을 사용해 점심·숙소 대기를 압축하지 않는다. 기존 수동 항목에는 시간 제약이 없고, 카드의 ‘방문 예정 시각(선택)’을 수정하거나 해제할 수 있다. 하루 출발을 앞당겨도 정해 둔 항목 시각은 유지하므로 더 일찍 방문하려면 해당 시각도 바꾸거나 비운다. 이는 사용자 계획 기준이며 실제 예약·체크인 가능 시간 인증이 아니다. 예정 시각은 일반 저장·장소 담기·초안 복구에서도 보존한다.

`/my-courses/add`는 기존 코스·일차를 선택해 장소/행사/음식점을 추가하며 같은 날 중복 장소는 건너뛴다. 기존 날짜·출발 시각·메모를 유지하고 서버에서 소유자·실제 참조 장소·수정 버전·실제 날짜 범위와 최대 30개 항목을 검증한다.

개인 코스의 `startDate`/`endDate`는 선택 사항이며 둘 다 없으면 날짜 미정 일정이다. 날짜를 정하면 시작·종료일과 항목의 상대 `day`로 실제 방문 날짜를 계산한다. 5일 제한은 없고, 날짜 미정은 양의 안전 정수 일차를 입력한다. [course-dates.ts](../apps/web/src/domain/course-dates.ts)가 UTC 달력 계산으로 월말·윤년·시간대에 따른 날짜 차이를 처리한다. 달력은 `0001-01-01`부터 `9999-12-31`까지 지원하며 긴 여행의 전체 날짜 배열을 생성하지 않는다. 시작일 변경은 상대 일차·순서와 여행 기간을 유지하고, 종료일 축소로 장소가 범위를 벗어나면 해당 날짜를 알리고 저장을 막는다. 장소를 자동 삭제하지 않는다. 날짜 지정·미정 전환, 기존 코스에 장소 담기, 저장·재조회와 초안 복구에서 날짜 메타를 보존한다. 입력 중 날짜가 한쪽만 있거나 범위가 맞지 않는 초안은 복원 가능하지만 DB 저장 전에는 날짜 쌍·범위와 모든 항목을 검증한다.

개인 편집기는 여행지·음식점·숙소 종류별 검색을 제공한다. [course-place-search.ts](../apps/web/src/domain/course-place-search.ts)가 검색어·지역·종류와 24개 페이지 계약을 검사한다. 여행지는 DB 검색, 음식점·숙소는 공개 DB 목록의 5분 서버 메모리 캐시와 동시 조회 합치기를 사용한다. 개인 데이터·검색 문장을 캐시에 저장하지 않으며 공공 API 호출도 추가하지 않는다. 무장애 필터는 여행지 검색에만 제공한다.

편집 중 초안은 `sessionStorage`의 계정·코스·쿼리별 키에 저장한다. 서버 버전이 같으면 자동 복원하고, 다르면 최신 DB 코스를 먼저 보여주며 ‘이전 초안을 새 코스로 복구’를 선택할 수 있다. 이전 초안으로 기존 서버 코스를 덮어쓰지 않는다. [personal-draft.ts](../apps/web/src/domain/personal-draft.ts)가 정상 초안과 이전 버전 백업의 키를 분리하고, 복구할 새 경로에 먼저 초안을 기록한 뒤 이동한다. 원본 백업은 새 코스의 DB 저장이 성공한 후 동일 사용자·버전일 때만 정리한다. 이는 같은 탭의 임시 저장이며 서버 저장·다른 기기 동기화가 아니다. 사용자 데이터는 공용 API 캐시에 넣지 않는다.

여행 취향은 `onboarding_preference`에 실제 저장한다. 개별 추천 ID 대신 10개 `topic:*` 관심 분야를 사용하며 기존 관심 테마 ID는 읽을 때 명시된 호환표로 변환한다. 관심 분야·페이스·동행은 전부 선택 사항이고 설정 화면에서 복원·변경·해제한다. 프로필 닉네임·소개 수정으로 취향을 생성하거나 덮어쓰지 않는다. 공유 Repository 객체나 공개 API 캐시에 사용자 선호를 보관하지 않으며 미로그인 검색은 공개 매칭을 유지한다.

| 경로                                                                | 화면                                                  |
| ------------------------------------------------------------------- | ----------------------------------------------------- |
| `/`                                                                 | 홈·목적 입력                                          |

[AppShell](../apps/web/src/components/app-shell.tsx)이 공통 메뉴·세션·언어·알림을 제공한다. `/result`도 PC 사이드바·모바일 하단 메뉴를 유지한다. 내비게이션의 `/saved` 표기는 ‘내 여행’으로 통일한다. [travel-ui.css](../apps/web/src/design/travel-ui.css)가 배경·표면·카드·주요 행동의 시각 계층을 보완한다. [화면 컴포넌트](../apps/web/src/components/screens/)는 도메인 props를 렌더하고 [nav](../apps/web/src/lib/nav.ts)가 경로를 만든다. 새로운 재사용 컴포넌트는 타입을 유지하고 `design/ui.tsx`의 기존 느슨한 타입은 화면 어댑터 경계에서 제한한다.

홈과 결과 수정 폼은 공통 [ThemeQueryInput](../apps/web/src/components/theme-query-input.tsx)의 한 줄 입력과 Enter 검색을 사용하고 한글 조합 Enter는 제출하지 않는다. 탐색 테마는 텍스트·지역과 별도 1~5일 기간 필터를 함께 적용한다. 기간 필터는 기본 기간의 정확 일치이고, 자연어 매칭의 기간 보조 점수와 구분한다. 선택 카드·칩은 강조 전후 테두리 폭을 유지하며 외부 사이트 링크는 공통 [ExternalLink](../apps/web/src/components/external-link.tsx)로 표시한다.

홈·탐색 기본 노출은 [theme-exposure.ts](../apps/web/src/domain/theme-exposure.ts)가 기간별 구성과 지역 중복을 고려해 선택한다. 홈은 1박·2박 코스를 중심으로 일부 요청에 장기 코스를 섞고, 탐색 첫 화면에도 숙박 여행을 충분히 포함한다. 같은 기간에서는 출처와 정상 장소 구성을 우선하며 요청별 seed로 동등 후보를 순환한다. 서버가 한 번 계산한 배열을 props로 전달하므로 같은 화면에서 필터·추가 로딩 도중 순서가 다시 섞이지 않는다. 카탈로그나 특정 기간의 필터 후보를 삭제하는 방식이 아니며 자연어 매칭의 관련성 순위도 바꾸지 않는다.

## 외부 호출과 장애 처리

공공 API와 환경변수 모듈은 서버 전용이다. `http.ts`가 키 주입·타임아웃·HTTP/XML 오류를 처리하며 키와 원문 인증 응답을 로그에 출력하지 않는다.

카탈로그 목록·검색은 DB에서 끝낸다. 장소 상세·날씨·대기질·집중률·무장애 자료는 필요한 화면에서 보강한다. 독립 데이터 호출은 병렬로 처리하며 하나의 외부 API 실패가 다른 자료까지 제거하지 않게 한다. 정상 빈 결과와 오류는 구분한다.

DB 카탈로그는 실제 연결이 필요하다. DB가 없거나 실패했을 때 런타임 샘플 카탈로그로 대체하지 않는다. 오류 경계와 재시도 화면을 제공하고, 실패한 DB 쓰기를 성공한 것처럼 처리하지 않는다. 공공 API 캐시는 DB 백업을 대신하지 않는다.

캐시 TTL·단일 인스턴스 제약과 실제 운영 진단은 [운영 안내](운영-준비-플랜.md)에 둔다.

### 목록 이어 읽기

[InfiniteScroll](../apps/web/src/components/infinite-scroll.tsx)은 목록 하단이 가까워지면 한 묶음을 추가한다. 테마는 이미 받은 추천 배열에서 18개씩, 행사는 받은 목록에서 12개씩 표시하므로 추가 공공 API 호출이 없다. 추천 순서는 필터를 조작하거나 항목을 추가 표시하는 동안 바꾸지 않는다.

여행지 검색과 개인 코스 장소 검색은 공개 DB 결과를 24개씩 누적하고 ID 중복을 제거한다. 추가 조회는 페이지 전체를 이동하지 않으며 선택 카드·지도·편집 중인 일정은 유지한다. 검색 조건 변경 시 첫 페이지로 초기화하고 이전 요청의 늦은 응답을 버린다. 모바일 개인 편집기의 검색 탭이 숨겨지면 추가 요청을 중지한다. 실패 시 앞 목록을 보존하고 사용자가 재시도하기 전에는 자동 요청을 반복하지 않는다. 빈 페이지·중복뿐인 페이지·마지막 페이지에서 멈춘다.

기존 `page=2` 같은 직접 링크는 해당 페이지부터 이어 읽으며 ‘첫 여행지부터 보기’로 돌아갈 수 있다. 추가 스크롤마다 URL의 페이지를 바꾸지 않는다. 목록은 상태·건수·완료 안내를 제공하고 키보드 포커스 및 관찰 API 미지원 환경에는 수동 이어 읽기 버튼을 제공한다. 본문 소개를 펼치는 버튼은 무한 스크롤 대상이 아니다.

### 홈의 고속도로 소통 정보

홈은 footer 위에서 영동·서울양양·동해(삼척–속초) 고속도로의 구간 소통을 보여준다. 교통 조회는 서버 Suspense 슬롯이므로 홈의 목적 입력과 추천을 기다리게 하지 않는다. 탐색의 지역 방문 통계에서는 중복 교통 영역을 제거한다.

도로공사 원천 구간명·방향·속도·관측 시각을 보존한다. 같은 구간·방향은 최신 시각의 검지기들 중 최저속도를 사용한다. 속도 0은 유효 관측이며 -1·빈 값·비정상 값은 미측정이다. 20분이 지난 자료는 현재 소통에서 제외한다. 40km/h 미만·40~80km/h 미만·80km/h 이상을 화면 구분에 사용하며 막대는 구간 수 비율이다. 실제 도로 길이·정체 원인·사용자 코스의 이동 시간으로 해석하지 않는다. 기존 원천 응답의 5분 캐시를 재사용한다.

## 언어와 관광 미디어

요청 언어는 `eumgil.lang` 쿠키를 서버에서 매번 읽는다. 공유 `LiveRepository`에 언어를 저장하지 않는다. 외국어 장소 검색은 5분 메모리 캐시의 공개 국문 후보를 언어별 공식 카탈로그와 연결한 뒤 일치하는 **국문 정본 ID**를 DB 검색 조건에 합친다. 지역·종류·무장애 필터, 페이지 24개와 정렬은 DB에서 유지한다. 외국어 카탈로그 전체를 카드마다 재요청하지 않는다.

사진·오디오는 상세 페이지의 `SpotMediaSection`에서 서버 Suspense로 독립 렌더링한다. 코스 후보나 목록 조회에서는 미디어 상세를 호출하지 않는다. 출처·촬영자·이용조건·원문 언어를 보존하고 음성 URL이 없는 안내에는 대본만 제공한다. 언어 변경 시 늦은 검색 응답을 폐기하고, 개인 일정의 장소 표시만 병합하여 날짜·순서·체류시간·사용자 메모를 보존한다.
