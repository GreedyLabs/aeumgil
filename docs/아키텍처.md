# 서비스 아키텍처

## 실행 구조

```text
App Router page / Server Action
          ↓
Repository 인터페이스 → LiveRepository
          ├─ PostgreSQL 카탈로그·사용자 데이터
          ├─ 도메인 순수 함수: 매칭·일정·혼잡·적합성
          ├─ 공공 API 클라이언트 → 공유 응답 캐시
          └─ 선택적 에이전트 루프 → 같은 도메인 함수와 조회 도구
```

화면 데이터는 [Repository](../apps/web/src/domain/repository.ts)를 통해 가져온다. [팩토리](../apps/web/src/data/index.ts)는 항상 `LiveRepository`를 반환한다. 런타임 목 저장소·데이터소스 전환 환경변수는 없다. 인증과 쓰기 검증은 서버에서 수행한다.

도메인 모델의 문구는 `LocalizedText { ko, en }`으로 전달하고 화면에서 `localized`로 선택한다. 한글 원천에 번역이 없는 경우 영어 안내의 완결성은 별도 과제로 남는다.

## 카탈로그와 사용자 데이터

[스키마](../apps/web/src/server/db/schema.ts)는 공공 카탈로그와 사용자 데이터를 분리한다.

- `spot_profile`, `course_template`, `course_template_item`, `commerce_profile`: 관광지·추천 템플릿·식당/숙소.
- `saved_theme`, `personal_course`, `review`, `visit`, `onboarding_preference`, `user_profile`: Keycloak `sub`에 연결한 앱 데이터.

카탈로그 수집은 운영 보조 명령으로 실행한다. 앱 부팅 때 수집·시드를 실행하지 않는다. `design/data.ts`와 런타임 샘플 평점·가상 장소는 제거되었다. 상세가 부족하면 실제 DB 기본정보와 미제공 상태를 유지한다.

개인 코스는 추천 복사 또는 빈 일정에서 시작하고 이동수단·하루 출발 시간을 함께 저장한다. `/my-courses/add`는 기존 코스·일차를 선택해 장소/행사/음식점을 추가하며 같은 날 중복 장소는 건너뛴다. 서버에서 소유자·실제 참조 장소·수정 버전·최대 일수/항목 수를 검증한다.

개인 편집기는 여행지·음식점·숙소 종류별 검색을 제공한다. [course-place-search.ts](../apps/web/src/domain/course-place-search.ts)가 검색어·지역·종류와 24개 페이지 계약을 검사한다. 여행지는 DB 검색, 음식점·숙소는 공개 DB 목록의 5분 서버 메모리 캐시와 동시 조회 합치기를 사용한다. 개인 데이터·검색 문장을 캐시에 저장하지 않으며 공공 API 호출도 추가하지 않는다. 무장애 필터는 여행지 검색에만 제공한다.

편집 중 초안은 `sessionStorage`의 계정·코스·쿼리별 키에 저장한다. 서버 버전이 같으면 자동 복원하고, 다르면 최신 DB 코스를 먼저 보여주며 ‘이전 초안을 새 코스로 복구’를 선택할 수 있다. 이전 초안으로 기존 서버 코스를 덮어쓰지 않는다. [personal-draft.ts](../apps/web/src/domain/personal-draft.ts)가 정상 초안과 이전 버전 백업의 키를 분리하고, 복구할 새 경로에 먼저 초안을 기록한 뒤 이동한다. 원본 백업은 새 코스의 DB 저장이 성공한 후 동일 사용자·버전일 때만 정리한다. 이는 같은 탭의 임시 저장이며 서버 저장·다른 기기 동기화가 아니다. 사용자 데이터는 공용 API 캐시에 넣지 않는다.

## 화면과 라우트

| 경로                                                                | 화면                                                  |
| ------------------------------------------------------------------- | ----------------------------------------------------- |
| `/`                                                                 | 홈·목적 입력                                          |
| `/result?q=...`                                                     | 자연어 추천 결과                                      |
| `/theme/[id]`, `/course/[id]`                                       | 추천 테마·조건별 코스                                 |
| `/discover?tab=themes\|places\|festivals\|visitors`                 | 테마·여행지와 지도·행사·지역 통계                     |
| `/spot/[id]`, `/festival/[id]`                                      | 여행지·행사 상세                                      |
| `/my-courses/new`, `/my-courses/[id]`                               | 개인 코스 생성·편집                                   |
| `/my-courses/add`                                                   | 기존 코스·일차를 골라 장소/행사/음식점 추가           |
| `/saved`                                                            | 내 여행                                               |
| `/profile`, `/profile/edit`, `/reviews`, `/settings`, `/onboarding` | 계정·취향·기록                                        |
| `/login`, `/doc`                                                    | 로그인·서비스 문서                                    |
| `/map`                                                              | 조건을 보존해 탐색의 여행지 탭으로 이동하는 호환 경로 |

[AppShell](../apps/web/src/components/app-shell.tsx)이 공통 메뉴·세션·언어·알림을 제공한다. `/result`도 PC 사이드바·모바일 하단 메뉴를 유지한다. 내비게이션의 `/saved` 표기는 ‘내 여행’으로 통일한다. [travel-ui.css](../apps/web/src/design/travel-ui.css)가 배경·표면·카드·주요 행동의 시각 계층을 보완한다. [화면 컴포넌트](../apps/web/src/components/screens/)는 도메인 props를 렌더하고 [nav](../apps/web/src/lib/nav.ts)가 경로를 만든다. 새로운 재사용 컴포넌트는 타입을 유지하고 `design/ui.tsx`의 기존 느슨한 타입은 화면 어댑터 경계에서 제한한다.

## 외부 호출과 장애 처리

공공 API와 환경변수 모듈은 서버 전용이다. `http.ts`가 키 주입·타임아웃·HTTP/XML 오류를 처리하며 키와 원문 인증 응답을 로그에 출력하지 않는다.

카탈로그 목록·검색은 DB에서 끝낸다. 장소 상세·날씨·대기질·집중률·무장애 자료는 필요한 화면에서 보강한다. 독립 데이터 호출은 병렬로 처리하며 하나의 외부 API 실패가 다른 자료까지 제거하지 않게 한다. 정상 빈 결과와 오류는 구분한다.

DB 카탈로그는 실제 연결이 필요하다. DB가 없거나 실패했을 때 런타임 샘플 카탈로그로 대체하지 않는다. 오류 경계와 재시도 화면을 제공하고, 실패한 DB 쓰기를 성공한 것처럼 처리하지 않는다. 공공 API 캐시는 DB 백업을 대신하지 않는다.

캐시 TTL·단일 인스턴스 제약과 실제 운영 진단은 [운영 안내](운영-준비-플랜.md)에 둔다.
