# 후보 2 — 분류·검토: 자연어 의도 → 테마 매칭 (+ 저품질/위험 입력 검토)

별도 학습 프로젝트의 설계 초안이다. 아래 목표·스키마는 현재 에움길의 제공 기능이나 운영 계획을 뜻하지 않는다. [문서 범위](README.md)를 먼저 참고한다.

> **포지션: 백업.** Week 1~4는 가장 깔끔하지만 Week 5(Tool calling)를 못 살린다. 난이도를 낮추고 싶을 때의 선택지.

## 1. 문제 정의 (Week 1)

### 사용자 / 업무

- **사용자**: 여행 의도를 자연어로 입력하는 방문자.
- **업무**: 의도를 강원도 특화 **테마로 분류**하고, 동시에 입력을 **위험/품질별로 검토**(정상 / 범위 밖 / 무의미 / 프롬프트 인젝션)해 통과 여부를 판정한다.
- 이미지 예시의 "분류·검토: 문의·초안을 유형 & 위험별로 분류"에 직접 대응.

### 입력 / 출력

- **입력**: 자연어 의도 문자열. 예) `"겨울에 눈 보면서 온천 하고 싶어"`
- **출력(schema)**:
  ```
  ClassifyResult {
    primaryThemeId: str
    altThemeIds: list[str]
    confidence: float          # 0~1
    reviewFlag: "ok" | "out_of_scope" | "nonsense" | "injection"
    rationale: {ko, en}
  }
  ```

### 데이터 출처

- **테마 카탈로그**: 실제 DB 카탈로그에서 추출하거나 학습용 fixture로 고정.
- **평가 데이터셋**: 라벨링된 의도-테마 쌍 + 위험 입력 케이스(경계·악성 입력 포함) — **합성 가능**(가장 만들기 쉬움).

### 성공 / 실패 기준

- **성공**: 정답 테마와 일치(top-1 / top-k), 위험 입력을 올바른 `reviewFlag`로 분류.
- **실패**: 오분류, 존재하지 않는 테마 생성, 위험 입력을 정상 통과시킴(안전 실패).

## 2. 커리큘럼 6주 매핑

| 주차       | 이 후보에서 하는 일                                                                             | 비고                                         |
| ---------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **Week 1** | 라벨 데이터셋 + schema + baseline(키워드 규칙 매칭)                                             | 가장 빠른 착수                               |
| **Week 2** | 모델 2종 분류 정확도·지연·token 비교                                                            | 명확                                         |
| **Week 3** | 오분류 케이스에 Human eval, 애매 케이스에 LLM-as-Judge                                          | judge 필요성은 약함(정답 라벨로 대부분 커버) |
| **Week 4** | 분류 프롬프트/few-shot 최적화 + ablation                                                        | 강함                                         |
| **Week 5** | **약점** — 순수 분류는 도구 호출 트레이스가 빈약. `list_themes` 조회 정도만 억지로 넣을 수 있음 | 커리큘럼 한 주를 못 살림                     |
| **Week 6** | CI에 분류 정확도 회귀 테스트 고정                                                               | 명확                                         |

## 3. 왜 백업인가

- **장점**: 정답 라벨이 명확해 데이터셋·baseline·회귀가 가장 깔끔하다. 혼동행렬·정밀도/재현율 등 정량 지표가 교과서적으로 붙는다.
- **단점**: Week 5(Tool calling / trace / 중복 호출)가 이 문제엔 본질적으로 필요 없어 한 주를 억지로 채워야 한다. "검증 가능한 **워크플로우**"라는 과정 취지에서 도구·트레이스 검증을 못 보여준다.
- **흡수 경로**: 이 분류 자체가 후보 1의 첫 단계(`list_themes` → 선택)에 포함되므로, 후보 1을 고르면 자연히 커버된다.
