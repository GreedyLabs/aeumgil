# 검증 안내와 릴리스 기록

검사 실행 결과·운영 반영·미검증 범위를 분리한다. 아래 날짜가 있는 릴리스 기록은 해당 코드의 증거이며 이후 변경까지 자동으로 보증하지 않는다.

## 실행 방법

```bash
pnpm --filter @eumgil/web exec next typegen
pnpm typecheck
pnpm --filter @eumgil/web test
pnpm build
pnpm --filter @eumgil/web verify:db
pnpm --filter @eumgil/web verify:api
pnpm --filter @eumgil/web verify:keycloak
pnpm --filter @eumgil/web verify:media
```

Next.js 빌드는 실행 중인 개발 서버와 같은 `.next`를 사용한다. 개발 서버를 멈추고 빌드한 뒤 필요한 모드로 다시 실행한다. 환경변수를 바꿨을 때에도 서버를 다시 시작한다.

### 브라우저

```bash
E2E_BASE_URL=http://localhost:3000 E2E_BROWSER_CHANNEL=chrome pnpm --filter @eumgil/web test:e2e
```

`E2E_BASE_URL`을 생략하면 Playwright가 개발 서버를 준비한다. `E2E_BROWSER_CHANNEL=chrome`은 설치된 Chrome을 사용할 때 지정하며 생략하면 Playwright 브라우저를 사용한다. 설정은 [playwright.config.ts](../apps/web/playwright.config.ts)를 따른다.

브라우저 검사는 실제 DB를 사용한다. 시작 시 `e2e-playwright` 사용자의 6개 테이블 행을 정리하고 테스트 중 생성·수정·삭제한다. 운영 사용자와 분리된 검증 DB 사용을 권장하며, 공유 DB에서 실행할 때는 전용 사용자 범위와 종료 후 정리를 확인한다. 같은 테스트 사용자를 쓰는 여러 실행을 병렬로 돌리지 않는다. 실행 중 화면 코드를 편집하면 HMR로 입력이 초기화될 수 있으므로 코드를 고정한 뒤 검사한다.

앱 인증 검사는 [세션 픽스처](../apps/web/e2e/helpers/session.ts)를 사용한다. 이것은 실제 Keycloak/Google 로그인 왕복을 검증한 것이 아니다. 운영 Keycloak/Google의 실제 왕복 검사 결과를 별도로 남긴다.

### API와 데이터

`verify:api`는 실제 API를 호출하고 키를 숨긴 응답 요약을 출력한다. 테스트 대역의 정규화 검사와 실제 승인·키·응답 검사를 구분한다. `verify:db`는 연결 외에 현재 조회하는 테이블·컬럼을 확인한다. 카탈로그 수집을 실행한 뒤에는 다음을 확인한다.

- 시군·원천 ID·좌표·분류와 사진 연결.
- 빈 추천 템플릿과 존재하지 않는 장소 참조.
- JSONB 배열의 타입과 idempotent 재실행.
- 무장애 목록 연결 수 및 조건 원문 보존.
- 사용자 기록이 수집/복구 과정에서 유지되는지 여부.

전체 320/390/768/1280/1440/1920px와 개인 코스 쓰기를 포함한 32개 시나리오는 로컬 프로덕션 빌드에서 수행했다. 운영 모바일 스모크와 전체 E2E의 실행 범위를 구분한다.

### 기존 연동 근거와 미검증 범위

2026-09-05 공공 API 8종 실제 응답과 카탈로그 기준선을 확인했다. 강원 원본 4,761건, 관광지 1,975(사진 1,744)·음식점 1,551·숙소 954·테마 119, 무장애 연결 661, 빈 템플릿/끊어진 참조 0/0이다. 수집 기준은 [카탈로그 문서](관광카탈로그-탐색-고도화-2026-09-05.md)를 따른다.

Keycloak 운영 테마 CSS·Google 버튼·파비콘 버전 스크립트와 독립 Keycloak 26.6.3의 PKCE 로그인 → 확인창 없는 로그아웃 → `prompt=none`의 `login_required`는 별도 검사에서 확인했다. **실제 Google 계정의 운영 전체 로그인 왕복과 SMTP는 미검증**이다. 앱 E2E의 인증 세션 픽스처가 이를 대신하지 않는다.

## 실 LLM 평가

검색은 키워드 순수 계산이며 코스 정리는 heuristic provider가 기본이다. `eval:real`은 별도 모델을 명시해 실행하는 실험으로 일반 단위 테스트에서 건너뛴다. 과거 실험 결과는 [에이전트 Evaluation 기록](에이전트-Evaluation-리포트.md)에 보존하되 현재 키워드 매칭이나 운영 응답속도의 근거로 사용하지 않는다.

## 독립 UX 검토와 수정

2026-09-05 개발 빌드를 PC 1440×844, 모바일 390×844·320×844에서 독립적으로 검토했다. 여행 계획의 다음 행동이 보이는지, 조건을 놓치지 않는지, 일정 편집이 끊기는지를 기준으로 지적하고 수정본을 다시 확인했다.
