# 환경변수와 Dockhand 배포

로컬은 루트 `.env`, 운영은 Dockhand 스택 환경변수를 사용한다. 공통 필수 값은 [.env.example](../.env.example)의 8개다. 원문 키·쿠키·DB 비밀번호를 저장소나 공유 로그에 기록하지 않는다.

## 필수 환경변수

| 변수                     | 용도                                                                          |
| ------------------------ | ----------------------------------------------------------------------------- |
| `AUTH_URL`               | 로컬 `http://localhost:3000`, 운영 `https://xn--wk0bk16buua.xn--3e0b707e`     |
| `DATABASE_URL`           | PostgreSQL URL. 운영은 기존 `shared-db` 네트워크의 `postgres:5432/eumgil_dev` |
| `AUTH_SECRET`            | Auth.js 세션 암호화 키. 운영 값을 임의 변경하면 기존 세션이 무효화됨          |
| `AUTH_KEYCLOAK_ID`       | 운영 `eumgil`                                                                 |
| `AUTH_KEYCLOAK_SECRET`   | Keycloak eumgil Client의 Credentials                                          |
| `AUTH_KEYCLOAK_ISSUER`   | `https://auth.greedylabs.kr/realms/eumgil`                                    |
| `DATA_GO_KR_SERVICE_KEY` | data.go.kr 15종 공통 Decoding 키. API별 활용 승인 필요                        |
| `EX_ROAD_SERVICE_KEY`    | data.ex.co.kr에서 발급한 별도 도로공사 키                                     |

공공 API별 별칭 키와 중복 앱 URL은 사용하지 않는다. Google OAuth 자격증명은 Keycloak에만 저장한다. 환경변수 변경 뒤에는 해당 서버 프로세스/컨테이너를 재시작해야 한다.

## 선택·인프라 설정

| 변수                                                                                         | 사용 조건                                          |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `DATABASE_SCHEMA`                                                                            | public 이외 스키마 사용                            |
| `EUMGIL_CACHE_DIR`                                                                           | 운영 `/app/cache`, named volume으로 유지           |
| `EUMGIL_DEBUG`                                                                               | `http,cache,repo` 등의 진단 로그. 기본 미설정      |
| `EUMGIL_WARMUP`                                                                              | `1`이면 개발에서도 캐시 워밍. 운영은 기본 실행     |
| `ROUTING_PROVIDER`                                                                           | 운영 `approx`. Kakao Mobility는 진행하지 않음      |
| `KEYCLOAK_ADMIN_CLIENT_ID`, `KEYCLOAK_ADMIN_CLIENT_SECRET`                                   | 탈퇴 시 인증 계정 자동 삭제용 별도 관리 Client     |
| `EUMGIL_AGENT_LLM`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL`, `OPENAI_TIMEOUT_MS` | 격리된 실 LLM 실험에서만 필요. 운영 기본 heuristic |
| `TAG`, `PORT`                                                                                | Gitops Compose 전용. 기본 latest·호스트 5180       |

코드에는 선택적 Kakao 어댑터가 남아 있으나 운영 Compose는 키를 전달하지 않는다. OSRM 서버도 배포하지 않았다. Keycloak 테마의 `EUMGIL_APP_URL`은 인증 서버 Compose 전용이며 앱의 필수 변수에 추가하지 않는다.

## 배포 흐름

[deploy.yml](../.github/workflows/deploy.yml): `main/dev push → Next 라우트 타입 생성 → 타입 검사·단위 테스트 → GHCR 이미지 빌드 → Dockhand webhook`.

- 이미지: `ghcr.io/greedylabs/eumgil`, moving tag `latest`, 고정 태그 `latest-<run_number>`.
- Gitops 저장소: `GreedyLabs/gitops`의 `eumgil/docker-compose.yml` 및 README. 앱 저장소에서 이미지를 만들고 Gitops는 pull하여 실행한다.
- Dockhand: Eumgil 스택 7. 컨테이너 배포 시 이미지 빌드는 하지 않는다.
- 캐시: UID 1001이 쓰는 `/app/cache` named volume. 사용자 DB와는 별도다.
- 현재 `main`과 `dev` 모두 같은 latest를 갱신하므로 두 브랜치의 push는 동일 운영 이미지에 영향을 줄 수 있다. 별도 개발 환경 분리는 후속 과제다.

로컬 `.env`와 비공개 `.env.dockhand.local`은 Git/이미지에서 제외한다. Dockhand가 실제로 주입하는 스택 변수와 Compose의 변수 이름을 대조한다. 파일을 업로드한 사실만으로 스택 변수 등록이 완료된 것으로 판단하지 않는다.

## 도메인과 인증 Callback

운영 URL은 [에움길.한국](https://에움길.한국)이다. OAuth 설정은 브라우저가 전송하는 ASCII 주소와 일치시킨다.

| Keycloak eumgil Client | 값                                                                |
| ---------------------- | ----------------------------------------------------------------- |
| Valid redirect URI     | `https://xn--wk0bk16buua.xn--3e0b707e/api/auth/callback/keycloak` |
| Post logout redirect   | `https://xn--wk0bk16buua.xn--3e0b707e/*`                          |
| Web origin             | `https://xn--wk0bk16buua.xn--3e0b707e`                            |
| Google 브로커 Callback | `https://auth.greedylabs.kr/realms/eumgil/broker/google/endpoint` |

로컬 개발 Callback은 운영 Client에 별도로 허용한 localhost 주소를 사용한다. 운영 도메인 이전이 Google 브로커 Callback의 호스트를 바꾸지는 않는다.

## 배포 절차

1. [검증 안내](검증.md)에 따라 타입·단위·브라우저와 해당 변경의 실연동 검사를 완료한다.
2. DB 변경이 있으면 이전 이미지와 호환되는 적용 순서·백업을 확인한다. `db:apply` 후 `verify:db`를 실행한다. 카탈로그 수집은 별도 검토하여 수행한다.
3. 기능 단위로 커밋하고 배포 브랜치에 push한다. Actions의 검사·이미지 빌드·웹훅 결과를 확인한다.
4. Compose 변경은 Gitops에 반영한 뒤 Dockhand Git 동기화·배포를 수행한다. 기존 스택 변수·볼륨·네트워크 설정을 유지한다.
5. 실행 컨테이너의 이미지 revision과 health를 확인한다. 운영 deep health, 주요 화면, 이미지·지도·로그인 복귀를 확인한다.
6. 회귀가 있으면 직전 검증된 고정 이미지 태그로 되돌린다. 이전 이미지와 DB 호환 여부를 먼저 확인한다.

`docker compose config`는 비밀값을 펼칠 수 있으므로 전체 출력을 공유 로그로 남기지 않는다. `/api/health`는 프로세스 상태, `?deep=1`은 DB와 캐시 상태를 확인한다. 외부 API 오류로 컨테이너를 재시작하는 구조는 사용하지 않는다.

마지막 실제 운영 커밋·Actions·검증 수치는 [검증 기록](검증.md)에 둔다.
