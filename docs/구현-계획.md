# 구현 현황과 후속 과제

완료 항목은 현재 코드의 계약을 뜻한다. 마지막으로 운영에서 확인한 릴리스와 테스트 수치는 [검증 기록](검증.md)에 따로 기록한다. 기획 목표·실험·배포 사실을 섞지 않는다.

## 현재 제공하는 기능

| 영역      | 구현                                                                                                                                         |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터    | DB 카탈로그, 강원 18개 시군, 실제 관광지·음식점·숙소, 원천 ID·사진·주소·좌표                                                                 |
| 자연어    | 여행 목적의 키워드·지역·제외 조건 매칭, 일치/부분/미일치 근거·입력 수정, 명시한 일정 조건 추출                                               |
| 추천      | 템플릿과 실제 후보를 조합하고 방문 순서·혼잡·이동 추정을 반영한 일정                                                                         |
| 탐색      | 테마·여행지·행사·지역 통계, 검색·지역·종류·무장애 안내 필터, 카드와 지도 연동                                                                |
| 장소·행사 | 실제 상세·사진·지도·주변 상권, 행사와 인근 장소의 개인 코스 연결                                                                             |
| 내 여행   | 개인 코스 생성·복사·편집·저장·삭제, 기존 코스/일차 담기, 여행지/음식점/숙소 검색 추가, 같은 탭 초안·다른 버전의 새 코스 복구, 추천 테마 보관 |
| 사용자    | Keycloak 인증·Google IdP, 프로필·취향·리뷰·방문 기록, 소유자 보호                                                                            |
| 동적 정보 | 공공 API 8종, 시각·출처·미수신 상태 구분, 응답 캐시                                                                                          |
| 운영      | 컨테이너·GHCR·Dockhand, 영속 캐시·헬스체크·오류/로딩/404 화면                                                                                |
| 검증      | 도메인·API·Repository 단위 검사, 실제 DB 브라우저 흐름, 별도 Keycloak 테마 검사                                                              |

과거 `Phase 0~5`의 구축 작업은 이 기능 표에 통합했다. 초기 9개 샘플 관광지·6개 테마, 미발급 API 키, 라우팅 전환 진행 중 등의 설명은 더 이상 현재 상태가 아니다.

## 제품 판단 기준

- 목적 입력에서 추천 이유를 이해하고 조건을 고칠 수 있어야 한다. 맞는 테마가 없을 때 일치한 것처럼 안내하지 않는다.
- 지도는 장소를 고르고 방문 순서를 판단하는 데 기여해야 한다. 독립 지도 메뉴를 늘리지 않는다.
- 추천 테마 보관과 개인 일정 저장을 명확히 구분한다. 일정 수정은 로그인 후 소유자 데이터로 보존한다.
- 모바일에서도 입력→판단→편집→저장이 이어져야 하며 과도한 스크롤이나 화면을 가리는 조작으로 끊기지 않아야 한다.
- 정보 부족·실패·빈 결과를 실제 값과 구분한다. 데이터가 없는 곳의 사진·혼잡·평점·접근 가능성을 만들지 않는다.

## 남은 한계와 확인 사항

| 우선순위 | 과제                                                              | 완료를 판단할 근거                                                    |
| -------- | ----------------------------------------------------------------- | --------------------------------------------------------------------- |
| 높음     | 실제 사용자가 목적 입력부터 개인 일정 저장까지 계획해 보는 관찰   | PC·모바일의 성공/이탈 지점, 입력 수정·장소 추가·저장 혼동 기록과 개선 |
| 높음     | 운영 Google 로그인 전체 왕복·세션 만료·로그아웃, SMTP 재설정 메일 | 실제 별도 검증 계정의 왕복 결과. 앱의 테스트 세션으로 대체하지 않음   |
| 높음     | 계정 탈퇴 시 Keycloak 자동 삭제 또는 수동 정리 절차               | 앱 데이터 6종 삭제와 인증 계정 잔존 여부를 각각 확인                  |
| 중간     | 실제 영업시간·휴무·예약·막차를 일정 제약에 반영                   | 원천 갱신·부분 결측·사용자 재확인까지 포함한 일정 검증                |
| 중간     | 여행 날짜와 일별 집중률·행사 기간·예보의 연결 강화                | 제공 기간 밖인 경우 추정/미제공 표시, 날짜별 결과 검증                |
| 중간     | 카탈로그 품질·현재성·누락 사진 점검                               | 명칭/좌표/분류/폐업/휴무·사진 원천의 표본 검수, 정기 갱신 기록        |
| 중간     | 화면 전체 영어·보조 기술 접근성                                   | 번역 원천 확인, 키보드·스크린리더·확대 사용의 전체 흐름 점검          |
| 중간     | DB 복원 훈련·운영 오류 집계·배포 환경 분리                        | 복구 소요시간·최근 복원 결과, 배포 전후 오류 비교                     |
| 확장 시  | 공유 캐시·분산 호출 제한                                          | 다중 인스턴스에서 TTL·키 격리·동시 갱신 검증                          |

자동 테스트의 통과는 여행 일정의 현장 실행 가능성이나 시각적 품질을 보증하지 않는다. 실제 이용 시간과 이동 방식의 오차를 함께 검토해야 한다.

## 이번 운영 범위에서 보류한 것

- Kakao Mobility 실경로 연동: 진행하지 않는다.
- OSM 기반 OSRM/Valhalla 서버: 방식 검토만 유지한다. 별도 배포하지 않았다.
- 실 LLM·RAG·멀티모달: 운영 기본 기능이 아니다. 키워드 방식의 품질·한계를 먼저 검증한다.
- Kakao/Naver 소셜 로그인: 로컬 참고 구성이 있어도 운영 제공 완료로 간주하지 않는다.
- 반려동물 동반 상세: TourAPI 추가 오퍼레이션 후보이며 아직 화면에 연결하지 않았다.

학습 실험의 모델·프롬프트·평가 계획은 [별도 학습 문서](ai-eval-course/README.md)에 둔다. 이 목록을 승인 없이 운영 기능 확정으로 바꾸지 않는다.
