# 기획·화면·사용 흐름 재점검 — 2026-09-05

## 점검 결론

기능 테스트가 통과해도 화면이 완성된 것은 아니었다. 기존 앱은 모바일 프레임을 데스크톱 사이드바 옆에 그대로 둔 구조였다. 본문 최대 폭 880px, 고정 높이와 본문 안쪽 스크롤, 줄무늬 테마 카드, 구현되지 않은 지도와 조작이 웹 서비스의 완성도를 떨어뜨렸다.

이번에는 `docs/제안서.md`와 루트의 프로토타입 이미지 6개를 기준으로 화면 역할과 이동 흐름을 다시 점검했다. 모바일 시안을 데스크톱에 단순히 확대하지 않고 목록·상세·폼별 레이아웃을 구성했다. 공공 API 7종은 실제 연동했으며, 아래에 남은 기획 차이와 배포 후 검증 범위를 구분했다.

## 공통 디자인과 화면 변경

- **문서 하나로 스크롤**: 앱의 고정 높이·본문 `overflow:auto`를 제거했다. 데스크톱은 232px 사이드바와 나머지 본문으로 구성한다. 1440px 화면에서 본문 영역은 약 1200px을 사용한다(스크롤바 폭에 따라 차이). 화면 가장자리에서 휠을 돌려도 문서가 스크롤되는 것을 테스트했다.
- **화면 목적별 폭**: 홈·탐색은 3열 테마 카드, 상세는 내용+요약 패널, 프로필은 활동 대시보드로 구성한다. 편집·설정·약관은 읽기 쉬운 폭으로 제한한다. 모바일에서는 순서와 여백을 재배치하며 내비게이션 5개(홈·탐색·지도·저장·프로필)가 하단에 남는다.
- **실제 콘텐츠**: 테마 사진은 해당 테마에 포함된 실제 DB 관광지 사진에서 분위기가 맞는 장소 순으로 선택한다. 음식점·숙박의 사진·주소·연락처·좌표가 DB 정규화 중 사라지던 부분을 복구했다. 자료가 없는 장소에는 다른 장소의 사진을 대입하지 않는다.
- **텍스트와 조작**: 페이지 제목 계층, 버튼 이름, 선택 상태, 터치 영역과 키보드 포커스, 도움말과 빈 상태를 정리했다. 매칭 완료 뒤 2.1초를 추가로 기다리던 타이머를 없앴다.

행사 기능은 **TourAPI 안의 추가 오퍼레이션**이다. 7종 중 4종째 API를 완성했다는 뜻은 아니다. 지도는 [OpenStreetMap embed](https://wiki.openstreetmap.org/wiki/Export), 행사는 [한국관광공사 국문 관광정보](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578)를 사용했다.

## 검증

- Vitest **165개 통과**, 실 LLM 평가 1개 skip.
- 앱 Playwright **19개 통과 / 53.2초**. 실제 `eumgil_dev` DB·공공 API, 자연어 조건 전달/변경, 저장·리뷰, 검색, 지도 선택, 행사 탭, 로그인 복귀 안내, 비회원 보호와 회원 화면.
- 주요 9개 화면 × **320·390·768·1280·1440·1920px**: 가로 넘침 없음. 회원 프로필·편집·리뷰·설정·온보딩은 390·1440px 추가 확인.
- 1440px에서 본문이 사이드바를 뺀 가용 폭의 90% 이상을 쓰고, 본문 안쪽 스크롤 없이 바깥쪽 휠로 문서가 스크롤되는 것을 검증.
- TypeScript strict 타입 검사·Next.js 15.5.19 프로덕션 빌드 통과.
- **실제 Keycloak 26.6.3 컨테이너**: 320·390·768·1440px 로그인/회원가입/재설정 및 오류 표시·비밀번호 보기·임시 사용자 로그인, Playwright **5개 통과 / 2.8초**. 운영 DB와 분리된 H2 미리보기. 원격 운영 계정 인증 검증과 구분한다.
- 브라우저로 홈·코스·장소·지도·앱 로그인·Keycloak 테마의 데스크톱/모바일 배치와 실제 사진·지도 로딩을 시각 점검했다. 자동 가로 넘침 검사가 시각 품질 전체를 보증하는 것은 아니다.

앱 E2E의 인증은 테스트용 Auth.js 쿠키이고, 사용자 데이터는 `e2e-playwright` 전용 행만 사용한다. 앱 DB의 E2E 전용 행은 검증 종료 후 모두 정리했고 잔여 0건을 확인했다. 실제 Keycloak 인증 테스트는 별도 미리보기 계정이다. SMTP 메일 발송과 원격 소셜 계정 인증은 검사하지 않았다.

## 이어서 진행할 작업

1. **새 도메인 배포**: 에움길.한국 기준 새 이미지·Gitops compose·통합 환경변수를 함께 배포하고 실제 계정 왕복을 검증한다.
2. **공공 데이터의 활용 확대**: 7종 호출과 화면 연결은 완료했다. 예측 날짜와 여행 날짜 연결, 노선 관측과 실제 코스 경로 대응을 추가 개선한다.
3. **코스 편집과 이동 품질**: 수동 대체지 적용, 선택 조건의 저장 모델, 식당·숙소 포함 실제 경로, 영업시간/휴무/막차 데이터를 함께 다룬다.
4. **카탈로그 확대**: 이미지 없는 장소 및 소수 권역의 콘텐츠를 보강한다. 관광지와 상권의 좌표·영업 정보·시즌별 적합성을 검수한다.
5. **운영 사용자 검증**: 실제 계정 왕복/소셜/탈퇴, SMTP 및 문의처, 영어·접근성 전 과정 회귀를 완료한다.

## 추가 UI·API 확인

일별 예측은 기본 7일·펼치면 30일, 관광지 사진/교통은 접을 수 있게 배치했다. 장소별 이용 시간·주소·주차·문의처를 표시하며 상세 요약 아래에 지도·코스 버튼을 모았다. 탐색에 권역별 방문 통계와 해당 지도 필터 이동을 추가했다. 관광지 8곳 contentId를 실대조했고 사천해변과 속초시장 오매칭을 바로잡았다.

환경변수 전환 뒤 개발 서버를 재시작해야 새 키를 읽는다. 첫 E2E의 2건 실패는 재시작 누락 및 이전 문구를 기대한 assertion으로 확인했고 수정 후 통과했다. 사진 테스트는 요소 존재뿐 아니라 naturalWidth로 실제 로딩을 검사한다. 최신 검증 결과는 AGENTS.md 상단을 기준으로 한다.
