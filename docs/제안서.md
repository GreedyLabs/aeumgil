# 에움길 서비스 기획

강원특별자치도의 여행 목적과 실제 방문 여건을 함께 고려하는 여행 계획 서비스다. 공공 관광정보를 실제로 조회하고 사용자가 추천을 자신의 일정으로 바꾸는 데 집중한다.

## 해결하려는 문제

관광지 목록만으로는 내 여행에 맞는 장소를 고르기 어렵다. 비슷한 분위기의 장소라도 이동 거리, 날씨, 혼잡, 동행자의 접근 조건에 따라 방문 경험이 달라진다. 유명 장소를 발견하는 것에서 끝나지 않고 주변 장소와 연결해 실행 가능한 일정의 초안을 만드는 것이 목표다.

강원은 해안·산악·호수·도시·접경 문화권의 특성이 다르다. 지역과 관심사를 함께 다루고, 한 곳의 유명 관광지에 선택이 쏠릴 때 같은 권역의 대체 후보를 제시한다. 실제 혼잡 분산 효과나 지역 소비 증가를 이미 입증한 것으로 주장하지 않는다.

## 핵심 사용자 흐름

1. **목적 표현**: 홈의 한 줄 입력에 “강릉에서 아이와 바다 산책”처럼 목적을 적고 Enter 또는 검색 버튼으로 제출한다. 한글 조합을 확정하는 Enter는 검색으로 이어지지 않는다. 테마 키워드와 지역, 명시한 일정 조건을 사용해 추천 후보를 좁힌다.
2. **추천 판단**: 테마와 포함 장소, 일수·이동 추정·방문 여건을 비교한다. 공식 관광자료를 참고해 편집한 코스는 출처와 도착·귀가 기준을 함께 읽는다. 맞지 않으면 입력을 고치거나 지역·기간별로 탐색한다.
3. **일정 편집**: 추천을 내 코스로 복사하거나 빈 일정부터 만든다. 이름·메모·실제 시작일과 종료일 또는 날짜 미정 일차·방문 순서·체류시간·이동수단·하루 출발 시간을 수정한다. 개인 일정에는 추천 기간 선택지의 5일 상한을 적용하지 않는다.
4. **장소 보강**: 여행지 또는 행사 상세에서 실제 안내와 위치, 주변 여행지·음식점을 확인한다. 새 코스를 만들거나 기존 개인 코스와 일차를 골라 담는다. 개인 편집기에서도 여행지·음식점·숙소를 종류별로 찾아 추가할 수 있다.
5. **저장과 재방문**: 로그인 후 개인 코스를 저장하고 내 여행에서 다시 연다. 방문 기록·리뷰와 취향은 별도 사용자 데이터로 관리한다. 저장한 관심 분야는 조건이 동등한 추천의 보조 순위에, 페이스·동행은 명시하지 않은 추천 조건의 기본값에 반영한다.

결과 화면은 공통 메뉴와 추천 근거·접을 수 있는 입력 수정 기능을 제공하고 사용자가 후보를 고른 뒤 코스로 이동한다. 모바일에서는 추천 코스로 가는 핵심 행동을 큰 사진보다 먼저 제시한다. 일치하는 테마가 없으면 임의 추천으로 자동 이동하지 않는다.

목적 입력과 여행지 검색은 역할이 다르다. 목적 입력은 분위기·활동을 테마에 연결하고, 여행지 찾기는 장소명·주소·종류·지역·무장애 안내 여부로 실제 장소 목록을 좁힌다.

## 화면별 책임

| 화면           | 사용자가 결정하는 것                  | 주요 결과                                                                         |
| -------------- | ------------------------------------- | --------------------------------------------------------------------------------- |
| 홈             | 어떤 여행을 하고 싶은가               | 목적 입력·대표 추천·지역 탐색                                                     |
| 추천 결과·테마 | 어떤 추천이 의도에 맞는가             | 매칭 근거·포함 장소·코스 진입                                                     |
| 추천 코스      | 일수·속도·동행·이동 조건이 적절한가   | 날짜별 일정·방문 순서 지도·내 코스 복사                                           |
| 탐색           | 어느 지역·장소·행사를 갈 것인가       | 테마 검색·지역·1~5일 기간 필터, 여행지/행사/방문 통계, 지도 선택과 상세 진입 분리 |
| 여행지 상세    | 방문 조건을 감당할 수 있는가          | 사진·이용 정보·날씨·대기질·예측·무장애 원문·주변 상권                             |

| 개인 코스      | 내 일정에 무엇을 어떻게 배치할 것인가 | 실제 날짜 또는 날짜 미정 일차·30개 항목, 이동 방식·출발 시간, 초안 복구·저장      |

| 프로필·기록    | 내 취향과 방문 경험은 무엇인가        | 관심 분야·페이스·동행의 복원/저장/해제, 방문·리뷰·계정 설정                       |

PC는 탐색 목록과 지도, 일정과 요약을 함께 비교할 수 있는 폭을 사용한다. 모바일은 핵심 행동과 읽는 순서를 유지하고 지도·긴 설명은 필요할 때 펼친다. 모바일 개인 코스는 일정과 장소 추가를 전환하고 하단 저장 동작을 유지한다. 초안은 현재 탭에서 복구하며 DB 저장과 구분한다. 서버 버전이 바뀐 초안은 기존 코스를 덮어쓰지 않고 별도 코스로 복구할 수 있다. 공통 메뉴·입력·선택창·카드·포커스 규칙을 공유한다.

선택된 카드는 테두리 두께 때문에 크기나 인접 카드 위치가 달라지지 않게 강조한다. 카드 안의 정보·행동과 섹션 사이의 간격을 구분하고, 외부 사이트로 이동하는 링크에는 외부 링크 표시를 제공한다. 로그인·추천 결과·취향 설정에서도 공통 메뉴를 유지한다.

## 추천 일정의 구성 원칙

짧은 지역 코스와 여러 날 머무는 편집 코스를 함께 제공한다. 다일 코스의 장소·일자·체류시간·공식 참고 링크는 [큐레이션 정의](../apps/web/src/domain/curated-courses.json)를 정본으로 삼는다. 관광기관의 원문을 그대로 재배포하는 상품이 아니라 실제 DB 장소를 연결하고 에움길이 일차와 체류시간을 재구성한 제안이다. 기사 사진과 본문을 복제하지 않으며, 사진은 실제 관광정보의 출처·이용 조건을 따른다.

편집 코스는 첫날 점심 이후 도착과 마지막 날 오후 귀가 여유를 전제로 한다. 구체적인 시작·관광 종료 시각은 코스별로 다르며 ‘관광 종료’가 집 도착 시각을 뜻하지 않는다. 긴 놀이공원·전시·숲 체험을 모두 한 시간으로 줄이거나 장소 수를 채우기 위해 하루에 밀어 넣지 않는다. 기본안의 일자별 순서와 긴 체류 구성을 유지하고, 사용자가 조건을 바꾸면 실제 이동과 이용 조건을 다시 살핀다.

같은 날 관광지·식당·숙소 사이의 이동 추정은 직전 방문 종료 뒤에 더한다. 집에서 첫 장소까지, 숙소에서 다음 날 첫 장소까지, 마지막 장소에서 집까지의 이동은 별도 여유가 필요하다. 개인 코스로 복사할 때 각 날짜의 첫 방문 시각을 가져와 오후 도착·다음 날 오전 출발을 유지한다. 이후에는 편집기의 날짜별 출발 시간·장소 순서·체류시간을 기준으로 다시 계획하며 특정 날짜의 시각만 바꾸거나 기본 하루 출발 시간으로 되돌릴 수 있다.

복사한 일정의 점심·숙소 등 개별 방문 예정 시각도 유지한다. 앞선 일정이 일찍 끝나면 예정 시각까지 여유를 두고, 늦어지면 이동·체류를 마친 뒤 도착하도록 계산한다. 장소별 시각은 수정하거나 비울 수 있다. 출발만 앞당겨 예약이나 체크인 기준까지 자동으로 앞당기지는 않는다.

홈은 1박·2박 추천을 중심으로 간헐적으로 긴 여행을 보여 주며, 탐색 첫 화면에도 다양한 숙박 기간과 권역을 섞는다. 같은 기간의 비슷한 후보는 방문마다 순환하되 한 화면에서 필터를 바꾸거나 더 볼 때 순서를 다시 섞지 않는다. 당일 코스도 전체 카탈로그와 기간 필터에서 계속 찾을 수 있다.

날짜를 정하지 않아도 일차별로 먼저 계획할 수 있다. 실제 날짜를 정하면 각 장소의 방문 날짜를 표시하고, 종료일을 줄여 장소가 범위를 벗어나면 해당 날짜를 알려 수정하게 한다. 사용자 장소를 자동 삭제하지 않는다. 취향도 전부 선택 사항이며 설정하지 않은 사용자에게 임의 값을 채우지 않는다.

## 제공 범위와 후속 방향

현재 자연어 처리는 단어와 테마 키워드에 의한 약식 매칭이다. 자유 서술의 모든 의도나 복잡한 부정을 완전히 이해하는 대화형 여행 설계자로 표현하지 않는다. 실 LLM은 별도 검증을 거쳐야 하는 선택적 확장이다.

지도는 실제 위치와 방문 순서를 보여주고 이동시간을 추정한다. 영업시간·예약·휴무·막차·실제 도로 경로를 모두 만족하는 일정을 보장하지 않는다. 무장애 이동 경로 계산도 제공하지 않는다.

다음 고도화는 사용자 입력의 모호함을 줄이는 매칭 근거, 일정 제약 확인, 카탈로그 정보 갱신, 실제 사용자 관찰에 기반한다. 범위 밖 기능을 현재 제공한다고 쓰지 않는다. 상세 우선순위는 [구현 현황](구현-계획.md)을 따른다.
