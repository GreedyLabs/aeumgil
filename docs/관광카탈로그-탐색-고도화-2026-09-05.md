# 관광 카탈로그·탐색·개인 코스 고도화

## 화면의 역할

홈은 여행 목적 입력, 대표 추천 세 가지(강릉 바다·양구 예술·철원 명소), 지역 탐색을 먼저 보여준다. 전체 목록은 탐색에 둔다. 지도는 독립 주 메뉴 대신 여행지 선택의 위치 확인과 코스별 방문 동선에 사용한다.

- **탐색 → 여행지 찾기**: 검색·18개 시군·종류·무장애 안내 보유 여부 필터, 24개 단위 DB 페이지 조회. 카드 선택은 지도만 갱신하고 ‘상세 보기’만 상세로 이동한다. 선택 카드는 테두리·배경·체크 표시로 강조한다. 모바일은 가로형 카드와 선택 시 여는 지도, 닫은 후 선택 카드로 돌아오는 흐름이다.
- **추천 코스**: 날짜별 번호 마커, 식당·숙소를 포함한 방문 순서, 구간별 이동 추정. ‘내 코스로 편집’으로 추천의 현재 조건을 반영한 일정을 복사한다.
- **내 여행**: 직접 만든 개인 코스와 저장한 추천 테마를 분리한다. 고정된 ‘최근 본 장소’ 샘플 목록은 제거했다.
- **개인 코스**: 이름·메모, 장소 추가/제거, 순서·날짜·체류시간 변경, 저장·재조회·삭제. 최대 5일·30곳, 같은 날짜 중복 장소 제한. 오전 9:30부터 이동·체류 추정 시각을 보여주고 늦은 일정은 조정을 안내한다. 행사도 하나의 일정 항목으로 저장한다.
- **축제·행사 상세**: `/festival/[id]`. 기간·장소·요금·시간·주최·문의·공식 홈페이지·개요·사진·지도, 반경 10km 내 여행지/음식점. ‘행사와 함께 담기’로 행사+주변 장소의 개인 코스를 시작한다. 음식점의 지도·영업 정보는 Kakao 지도 링크를 유지한다.
- **교통 정보**: 관광지마다 반복하던 고속도로 텍스트를 제거했다. 탐색의 지역 방문 통계 아래에서 강원 연결 고속도로 3개 노선의 저속 관측 구간 수와 관측 시각을 보여준다. 관광지 현장 혼잡이나 코스 도착시간으로 표현하지 않는다.

## 실제 데이터와 선정 기준

2026-09-05 `KorService2/areaBasedList2` 강원(`lDongRegnCd=51`) 4,761건을 1,000개씩 다섯 번 호출해 수집했다. 18개 시군, 유효 좌표, 콘텐츠 유형과 관광 분류를 확인했다. 일반 소매점을 제외하고 관광지·문화시설·레포츠·시장/특화쇼핑을 관광지로, 음식점과 숙박·야영장을 식음/숙박으로 분리했다.

| --- | ---: |

| 실제 원천 사진이 있는 관광지 | 1,744 |
| 음식점 | 1,551 |

음식점·숙박 수에는 기존에 수집된 유효 장소도 포함한다. 사진이 없는 곳은 다른 장소 사진으로 채우지 않는다.

지역 추천 113개는 기존 큐레이션 6개에 더해 생성했다. 각 지역의 바다·숲·역사·전시·시장·체험 등의 분류와 대표 명소를 조합하며 3곳 간 직선거리를 0.4–20km로 제한했다. 정상·장거리 산행·통제구역·골프 등 짧은 방문 슬롯에 적합하지 않은 장소를 제외하고, 가까운 실제 식당을 연결했다. **한국관광공사 원천 정보를 활용한 에움길 추천이며 공식 인증 코스나 전수 현장 답사 결과가 아니다.** 운영시간·휴무·예약·실제 도로 동선은 개별 상세 안내와 함께 확인해야 한다.

자료는 [TourAPI 국문 관광정보](https://www.data.go.kr/data/15101578/openapi.do), [강원 관광 공식 사이트](https://www.gangwon.to/gwtour), [2025 강원 관광지도](https://www.gangwon.to/page/gwtour2022/images/map/2025_gwtourmap.pdf)를 참고했다. 관광공사의 분류 코드(`lclsSystmCode2`)와 원본 콘텐츠 ID·사진 출처를 보존한다.

`db:collect:gangwon --apply`는 카탈로그만 백업 후 upsert하며 사용자 기록과 기존 큐레이션 ID를 유지한다. `--input`으로 검토한 공개 스냅샷을 재사용할 수 있다. 원문 스냅샷·DB 백업은 `.cache/`에 보관하고 Git과 이미지에서 제외한다. 프로토타입 시드 명령은 중단했으며 `design/data.ts`도 삭제했다. 기존 JSONB 배열의 이중 문자열화와 가상 카페·샘플 평점은 별도 복구 스크립트로 정리했다.

## 무장애 정보

[한국관광공사 무장애 여행정보](https://www.data.go.kr/data/15101897/openapi.do)의 `KorWithService2`를 기존 `DATA_GO_KR_SERVICE_KEY`로 실호출했다. 강원 1,517건 목록 중 현재 관광지 661곳이 같은 콘텐츠 ID로 연결된다. 목록 두 번 호출로 보유 여부만 DB에 저장하고, 실제 `detailWithTour2`는 상세를 열 때 24시간 공유 캐시를 사용한다.

‘안내 있음’은 이동 가능 인증이 아니다. 예를 들어 박수근미술관의 주출입구 계단·보조출입구 경사로, 3관에만 있는 엘리베이터, 휠체어 대여 수량/조건처럼 조건과 제약을 그대로 표시한다. ‘없음’도 보존하고 빈 항목을 ‘가능’으로 바꾸지 않는다. 개인 코스의 장소 검색에도 같은 필터를 제공한다.

## 사용자 데이터와 호출 절감

화면은 계속 Repository 인터페이스를 사용한다. `personal_course`는 Keycloak sub 소유자 조건을 모든 읽기·수정·삭제에 포함하고, 수정 시 읽었던 버전을 함께 비교해 다른 탭의 편집을 덮어쓰지 않는다. Server Action에서 입력 범위와 실제 장소 존재를 검증한다. 탈퇴 시 개인 코스도 삭제한다. 사용자 ID·개인 코스는 공용 API 캐시에 저장하지 않는다.

검색·카드 렌더는 DB에서 끝낸다. 행사/관광지 사진·이용 안내·무장애 상세는 24시간, 행사 목록 1시간, 기상/대기질 10분, 자외선 1시간, 집중률 6시간, 교통 5분 캐시를 사용한다. 동일 요청 합치기와 정상 빈 결과·오류 재호출 제한, Docker 영속 캐시를 유지한다. 기본 LLM은 요청대로 heuristic이다.

## UI 공통 규격

PC 사이드바는 256px, 중간 폭에서는 224px, 접었을 때 76px이다. 토글은 같은 위치에 고정하고 방향만 바뀐다. 계정 영역은 공통 Avatar와 36px 원형 사진/이니셜을 사용한다. 지역·날짜 선택창은 공통 Select로 통일하며 네이티브 키보드/모바일 동작을 유지한다. 텍스트 입력도 기존 필드 토큰을 공유한다. 문서 스크롤과 모바일 하단 메뉴 안전 여백은 유지한다.

## 길찾기 검토

사용자 결정에 따라 **이번에는 Kakao Mobility 실경로 연동과 OSRM 신규 운영을 진행하지 않는다.** 현재 지도는 OSM 배경에 방문 순서를 점선으로 연결하고 좌표 기반 이동 추정임을 명시한다. 실제 도로 경로나 실시간 교통 도착시간을 제공한다고 표시하지 않는다.

OpenStreetMap은 지도 데이터다. 경로 계산에는 [OSRM](https://project-osrm.org/docs/v5.24.0/api/) 또는 [Valhalla](https://valhalla.github.io/valhalla/) 같은 별도 엔진이 필요하다.

| 방식 | 가능한 역할 | 운영 검토 |
| --- | --- | --- |
| 현재 Leaflet + OSM | 장소·날짜별 동선 표시 | 지도 타일 이용 정책과 출처 표시 유지 |
| 자체 OSRM | 자동차 도로 경로·거리·시간·구간 매트릭스 | 한국 OSM 데이터 다운로드·전처리·업데이트, 저장 공간·메모리 필요. 프로파일별 데이터 준비 필요 |
| 자체 Valhalla | 여러 이동 방식과 경로 비용 모델 | 데이터 구성과 운영이 더 복잡하며 대중교통은 별도 시간표 데이터 필요 |
| 관리형 경로 API | 사업자가 제공하는 실경로·시간 | 키·요금·호출 정책 및 한국 도로 품질 확인 필요 |

공개 데모 경로 서버를 운영 서비스의 필수 의존성으로 두지 않는다. 자체 서버를 선택하면 현재 이동시간 포트 뒤에 어댑터를 연결하고 도로 geometry만 지도에 전달하면 된다. OSM 데이터만으로 무장애 이동 경로의 계단·경사·통행 가능성을 보증하지 않는다. 지도는 [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 사용자 화면에 필요한 타일만 요청하고 출처를 표시한다.

## 인증·배포 검증

HTTPS Auth.js의 `__Secure-` 세션 쿠키와 분할 쿠키를 올바르게 읽고, 서버에서 ID 토큰을 확보한 뒤 앱 세션 제거 → Keycloak end-session으로 이동한다. 단위 테스트와 독립 Keycloak의 PKCE 로그인·확인창 없는 로그아웃·이후 `prompt=none`의 `login_required`를 확인했다. 앱 E2E 세션 픽스처와 실제 Keycloak 인증 검증은 구분한다.

최종 배포는 dev 브랜치의 타입 검사·유닛 테스트·GHCR 이미지 빌드가 통과한 뒤 Dockhand에서 진행한다. 개인 코스 테이블과 무장애 컬럼은 이미 운영 DB에 적용했으며 기존 이미지와 호환된다. 앱 시작 시 데이터 수집이나 시드를 실행하지 않는다.

### 배포 전 확인

- TypeScript 및 단위 테스트 197개 통과(실 LLM 평가는 요청에 따라 1개 미실행).
- Chrome E2E 29개 시나리오 확인. 개발/프로덕션 빌드에서 실행하고 Next.js 스트리밍의 임시 DOM과 중복 alert를 기다리는 테스트 선택자를 보정해 실패 항목을 재검증했다. 320/390/768/1280/1440/1920px, 실제 DB 개인 코스 CRUD·타 사용자 404·두 탭 저장 충돌·추천 복사·행사 포함·무장애·리뷰/회원 흐름 포함.
- 공공 API 8종 실제 검증 통과. 행사와 관광지 목록은 DB/캐시를 재사용한다.
- 운영 Keycloak 테마 CSS는 저장소와 일치, Google 버튼 정상. 파비콘은 CDN의 오래된 캐시가 확인되어 부모 템플릿을 유지하고 아이콘 URL에 해시 버전을 붙이는 스크립트로 보완했다. 로컬 Keycloak 26.6.3에서 로드 확인.

- Next.js 프로덕션 빌드 통과. 행사장 OSM MapLibre 타일·인근 실제 사진 로드까지 모바일 Chrome에서 확인했다.
