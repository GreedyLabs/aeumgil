## 이번 변경

### 공공 API와 데이터 신뢰성

- TourAPI·기상청·에어코리아 호출을 HTTPS로 통일했다. HTTP 200 안의 `resultCode` 오류도 실패로 처리하고, 응답 본문 수신까지 타임아웃에 포함했다.
- 기상청 예보는 발표 직후 첫 행 대신 현재 KST 시간대의 예보를 선택한다. 기온·강수확률·풍속·강수형태·하늘상태 누락을 0/맑음으로 변환하지 않는다.
- 에어코리아는 강원 전체 응답을 공유 캐시에 한 번 저장한 뒤 측정소별로 선택한다. 여러 지역의 동시 조회가 전체 목록을 반복 요청하지 않는 것을 단위 테스트로 확인했다.
- 관광 상세·날씨·대기질을 독립적으로 보강한다. 한 원천의 장애가 다른 원천의 성공 결과를 지우지 않는다. 누락된 날씨·대기질은 화면에 확인 중으로 표시하고 방문 적합도 점수도 숨긴다.
- 캐시의 미래 타임스탬프·손상 항목을 거부하고, 같은 원천이 실패하면 30초간 재호출을 억제한다. 날씨 캐시 버전을 바꿔 이전 정규화 결과를 재사용하지 않는다.
- 테마 목록의 스팟 조회 N+1을 제거했다. 스팟 상세 평점·리뷰 수는 앱 리뷰 테이블에서 집계한다.
- `verify:api`가 연결 성공 여부뿐 아니라 데이터 수·필수 필드·예보 시각·측정소 매핑·요청 소요시간을 JSON으로 출력한다. 키와 원문 응답은 출력하지 않는다.

### 추천과 코스

- 자연어의 명시적 일수·동행·이동수단·페이스·출발 권역을 코스 옵션으로 전달한다. 예: “부모님과 대중교통으로 1박 2일 바다 여행” → `days=2&companion=family&transport=transit`.
- URL 옵션을 허용 목록으로 정규화했다. 조건 패널은 뒤로가기·서버 갱신 후에도 현재 URL과 일치한다.
- 중복 장소, 비어 있는 추가 날짜, 누락된 식사·숙박 참조, 마지막 날 숙박을 제거했다. 템플릿에도 페이스별 방문 수를 적용한다.
- 에이전트의 순서 변경 후 체류·예상 이동시간을 검사해 겹치는 시간을 조정하고, 20시 이후까지 밀리는 방문과 1시간을 초과하는 도보 구간을 제외한다.
- 대체지는 같은 지역·테마 후보를 우선하며, 후보가 없으면 빈 상태를 표시한다.

에이전트는 도구 호출과 순서 선택을 담당하고 일정의 실행 가능성은 순수 함수가 확인한다. LLM 출력만으로 시간 제약을 보장하기 어려워 마지막에 결정형 검사를 둔 것이다. 이동시간은 현재 관광지 좌표 사이의 근사값이며 식당·숙소까지 포함한 정밀 경로, 영업시간·막차·예약 가능 여부는 아직 보장하지 않는다. 도보 제약으로 요청 일수보다 실제 일정이 짧아질 수 있다.

### 모바일·웹 UI

- 홈을 DB 테마·장소와 실제 수신 가능한 방문 여건 중심으로 정리했다. 날씨 영역은 스트리밍해 기본 화면의 표시를 막지 않는다.
- 고정 날씨·대기질·교통, 임의 혼잡 그래프, 예시 평점 등의 표시를 제거했다. 예상 혼잡도와 미수신 정보를 구분한다.
- 공유, 탐색 검색, 한산한 장소 필터, 저장 화면 추가 버튼, 테마 코스 진입을 실제 동작에 연결했다. 구현되지 않은 알림·다크 모드·사진 업로드 조작은 노출하지 않는다.
- 사진은 `next/image` 크기 최적화와 실패 시 대체 표시를 사용한다. 실제 이미지가 없는 장소에 관계없는 사진을 표시하지 않는다.
- 320·390·768·1280px 폭에 맞춰 카드·타임라인·태블릿 레이아웃·터치 영역·하단 내비게이션·가로 목록을 보정했다. 폼 이름, 선택 상태, 키보드 포커스, 토스트 알림도 보강했다.
- 1차 점검 시 지도는 상대 위치 약도였으며, 이후 화면 재점검에서 실제 OpenStreetMap 위치 지도로 교체했다.

## 운영 실연동을 위해 남은 작업

1. 기획의 7종 중 구현된 클라이언트는 TourAPI·기상청 단기예보·에어코리아 3종이다. 관광 빅데이터 방문자수·집중률 예측·생활기상지수·도로공사 교통 4종은 미구현이다. 이번 변경을 7종 전체 실연동 완료로 보아서는 안 된다.
2. 관광지 이미지·개요와 상권 데이터의 범위를 확대하고 출처·사진 이용 조건을 실제 응답별로 확인한다. 현재 관광지 9개 중 DB 이미지 4개·큐레이션 개요 7개가 있으며 없는 이미지는 대체 표시를 쓴다.
3. Kakao Mobility 키가 있으면 실제 이동시간 경로를 검증한다. 실측 혼잡 데이터가 없는 현재 혼잡도는 모델 추정치로 유지한다.
4. 로그인·로그아웃·소셜 브로커·탈퇴를 실계정으로 점검한다. 서비스 문의처·운영 고지도 확정해야 한다.

```bash
pnpm --filter @eumgil/web verify:api > api-report.json
pnpm --filter @eumgil/web verify:keycloak
pnpm --filter @eumgil/web verify:db
pnpm --filter @eumgil/web verify:enrichment
pnpm --filter @eumgil/web test
pnpm --filter @eumgil/web typecheck
pnpm --filter @eumgil/web build
# 로컬 서버가 실행 중일 때만 URL을 지정한다. 생략하면 Playwright가 서버를 띄운다.
E2E_BASE_URL=http://localhost:3000 pnpm --filter @eumgil/web test:e2e
```

`verify:api` 종료 코드는 구현된 클라이언트 기준으로 0=성공, 1=호출/응답 오류, 2=키 누락이다. 미구현 4종은 별도 `pending` 배열로 출력한다. 브라우저 테스트는 `e2e-playwright` 사용자 데이터를 정리하므로 검증용 DB에서 실행한다.

## 후속 설정 확인

사용자 지정 기존 Keycloak `https://auth.greedylabs.kr/realms/eumgil`의 discovery HTTP 200과 issuer 일치를 확인하고 로컬 `.env`를 해당 서버로 변경했다. 클라이언트 ID는 `eumgil`, Client Secret은 관리자 콘솔의 Credentials에서 확인해야 한다. `AUTH_SECRET`은 별도로 생성하는 앱 세션 보호 키다. LLM은 사용자 요청대로 `heuristic`을 유지한다. 공공 API 3종은 같은 계정의 일반 인증키를 사용할 수 있으며 각 API 활용신청·승인은 별도다.

### DB 검사 실행 환경과 해결

검사는 컨테이너 내부가 아니라 macOS(Darwin)의 `/opt/homebrew/bin/node` 및 `nc`로 실행했다. 권한 확장 실행에서도 EHOSTUNREACH가 발생했으나 호스트 en0 라우트와 ARP 이웃 주소는 존재했다. 시스템 설정에서 DBeaver의 로컬 네트워크 권한은 켜져 있고 Codex를 실행하는 ChatGPT 앱의 권한은 꺼져 있는 것을 확인했다. 사용자가 ChatGPT 권한을 켠 뒤 같은 DB 주소로 연결에 성공했다. Docker는 앞선 화면 검증용 임시 PostgreSQL에만 사용했다.

실제 DB 연결 후 `spot_profile.description_ko`·`description_en` 컬럼 누락으로 화면 조회가 실패했다. 기존 `verify:db`는 이 컬럼을 검사하지 않아 성공으로 보고했다. 검증 스크립트에 현재 읽는 모든 카탈로그 컬럼과 `commerce_profile` 검사를 추가하고 누락 시 종료 코드 1을 반환하도록 수정했다. 기존 `db:apply`로 누락 컬럼을 추가하고 비어 있는 큐레이션 개요 7건을 보강한 뒤 전체 테이블·컬럼 검증이 통과했다. 전체 카탈로그 재시드는 하지 않았다.

개발 서버는 루트 `.env`의 실제 DB·공공 API 설정으로 전환했다. E2E 12개가 31.4초에 통과했으며 브라우저에서 실제 사진 로딩과 평창 날씨·대기질 표시도 확인했다. 원격 Keycloak의 `eumgil` 클라이언트는 localhost 콜백 주소를 받아 로그인 화면을 정상 표시했다. 사용자 로그인 완료는 별도 확인이 필요하다.
