# 실 LLM 평가 실험 기록 — 2026-07-11

이 문서는 **당시 로컬 모델을 사용한 학습 실험 기록**이다. 현재 운영은 키워드/heuristic 방식이며 이 결과를 현재 서비스의 추천 정확도·응답속도·보안 보증으로 사용하지 않는다. 실행 원문과 당시 상세 쿼리는 Git 이력에 있다.

## 당시 실험 조건

| 항목   | 조건                                                                          |
| ------ | ----------------------------------------------------------------------------- |
| 모델   | `unsloth/Qwen3.5-4B-GGUF:Q4_K_M`                                              |
| 서버   | 로컬 llama.cpp b9840, OpenAI-compatible                                       |
| 입력   | 고정 4개 케이스: 한산한 해변·유명 해변·한산한 산·막연한 요청                  |
| 데이터 | [sampleEvalContext](../apps/web/src/server/agent/eval/dataset.ts)의 고정 대역 |
| 비교   | heuristic 기준선과 실모델에 같은 룰브릭 적용                                  |
| 실행   | `pnpm --filter @eumgil/web eval:real`                                         |

네트워크 주소와 모델 설정은 현재 유효한 운영 접속 정보로 남기지 않는다. 재실험은 사용 가능한 endpoint·모델·입력 데이터를 명시해 별도 기록한다.

## 기록된 결과

| 지표                  | heuristic | 당시 실모델 |
| --------------------- | --------: | ----------: |
| 전체 룰브릭 통과      |       4/4 |         3/4 |
| 대표 테마 유효성      |       4/4 |         4/4 |
| 대안 테마 무결성      |       4/4 |         4/4 |
| 정상 종료             |       4/4 |         4/4 |
| 특정 혼잡 도구 경유   |       4/4 |         3/4 |
| 미등록 도구 호출 없음 |       4/4 |         4/4 |

실모델 4개 케이스의 총 실행은 약 130초였다. 별도 앱 경로 관찰에서는 정상 쿼리 5개의 응답이 24~92초 범위였다. 단일 장비·당시 코드·작은 표본의 관측값이며 다른 모델이나 현재 서비스로 일반화할 수 없다.

실패한 한산한 해변 케이스는 `estimate_congestion` 대신 `reorder_by_congestion`을 사용했다. 채점기는 전자 호출만 정답으로 보므로, 실제 추천의 혼잡 적합성과 도구 경유 규칙이 어긋날 수 있다. 이를 확인하지 않은 채 통과율을 맞추기 위해 규칙만 완화해서는 안 된다.

## 유지할 학습 포인트

- 모델 응답의 형식 흔들림에 대비한 파싱과 최종 ID 검증은 별도 계약이다.
- 같은 데이터셋·시각·도구 응답을 고정해야 모델과 프롬프트 변경을 비교할 수 있다.
- 특정 도구 호출 여부는 실제 코스 품질의 대리 지표다. 사용자 목적·제약 충족과 따로 평가해야 한다.
- 4개 사례에서 위반이 없었던 결과는 일반적인 안전성 증거로 충분하지 않다.
- 향후 모델 비교는 품질과 지연·호출량·폴백·오류를 함께 기록한다. 실험 결과가 운영 승인을 대신하지 않는다.
